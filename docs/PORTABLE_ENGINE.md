# Переносимый боевой движок D&D 2024

Версия движка 30.4.0, API пакетов 1. Это программный движок с ограниченным списком проверенных механик, а не полный набор правил всех классов. Исходный код одинаков для каждой кампании. Пакеты содержат данные, не JavaScript. Зависимости npm и сеть при сборке не нужны; необходимы Node.js 22+ и Python 3.10+.

После распаковки на другом компьютере или аккаунте:

```sh
node sdk/verify.js
node sdk/cli.js capabilities
node sdk/cli.js validate examples/portable/border-watch.json
node --test tests/test_content_packs.js tests/test_class_features.js tests/test_defenses.js tests/test_martial_features.js
python tools/build_combat.py --pack examples/portable/border-watch.json --output dist/battle.html
```

Откройте `dist/battle.html` в настольном браузере. Внутри — движок, данные и интерфейс. В примере нет изображений, поэтому участники показаны подписанными жетонами. Кнопка «Загрузить пакет кампании» принимает другой пакет JSON; сохранение включает его и продолжает работать после перезагрузки. Сохранения разных кампаний используют разные ключи.

Дополнительный пакет `examples/portable/class-defense-lab.json` содержит учебную партию с классовыми ресурсами, защитой и реакциями. Он проверяет перенос обработчиков, но не заменяет полный профиль любого официального класса. Параметры: `docs/CLASS_FEATURES.md`.

Весь тестовый пример — авторский учебный бой, не событие какой-либо живой кампании. Противник с ядовитыми когтями не является официальным статблоком D&D.

Изменение героя или противника: скопируйте пример, измените `id` кампании, описания `profiles`, `characters` и `encounters`, затем проверьте пакет. Параметры характеристик, атак и готовых возможностей меняются в данных. Общие описания способностей помещаются в `abilities`; участники ссылаются на их ID. Неизвестный обработчик, неподдержанная возможность или конфликт параметров останавливает загрузку. Формат и пределы описаны в `docs/CONTENT_PACKS.md`.

Для программного использования:

```js
const {createBattle, CombatTacticalAI} = require('./sdk');
const pack = require('./examples/portable/border-watch.json');
const {engine} = createBattle(pack, 'marsh-road', 123);
engine.initialize();
// Интерфейс обязан запросить решения игрока, если engine.s.pending заполнено.
// Команды всех участников проходят engine.dispatch(command).
```

Для новой механики добавляется один проверенный обработчик в общую библиотеку, его регистрация и тесты. Пакет не может сам исполнить код или включить старую ветку персонажа. Интерфейс поддерживает нынешние команды; отдельный новый вид активного действия также требует UI и политики NPC.

Сохранения старого движка v30 продолжают открываться. Сессии с классовыми ресурсами и новыми обработчиками используют оболочку v32; остальные сессии с пакетами — v31, чтобы старый интерфейс v30.1 не открыл их, пропустив новые эффекты. Внутренняя схема состояния остаётся v30; переносить её напрямую в старое ядро нельзя. API пакета, версия правил и версия движка — разные контракты.

Сюжетный пакет должен поступать от адаптера канона с ревизией и SHA-256. Экспорт результата не применяет его к кампании. Запись результатов — ответственность отдельного адаптера с проверкой исходного состояния, допустимых изменений и повторного применения. Пример не включает чьи-либо канонические данные, ключи доступа или планы ведущего. Данные пакета в браузере доступны игроку: тайны сюжета следует держать вне него.

`engine-manifest.json` фиксирует хеши файлов SDK. Для обновления обеих кампаний собирайте их одной выбранной версией SDK; не исправляйте независимые копии ядра в каждой кампании. Проверка хешей обнаруживает локальные изменения, но сама по себе не удостоверяет происхождение архива: получать его следует из доверенного репозитория.

Для повторной упаковки из исходного репозитория: `python tools/export_engine.py --output dist/combat-engine.zip`.
