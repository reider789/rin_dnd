# Контракт пакета v1

Исполняемый эталон — `core/content_pack.js`, поддерживаемые возможности — `core/capabilities.js`. `node sdk/cli.js capabilities` показывает их машиночитаемое описание. Полный пример — `examples/portable/border-watch.json`.

| Поле | Значение |
| --- | --- |
| `kind`, `version`, `api` | `dnd-combat-pack`, `1`, `1` |
| `id`, `revision` | Стабильный ID кампании и положительная ревизия содержимого |
| `rules_version` | `dnd-2024-2026-10` |
| `requires` | Имена обработчиков (`features`, `onHitCondition`) или `feature:extraAttack` и аналогичные |
| `abilities` | Общие определения возможностей по ID |
| `profiles` | Характеристики и возможности участников по ID |
| `characters` | ID героев → профиль, текущие ресурсы, доступное имущество |
| `encounters`, `default_encounter` | Карты и размещение участников, ID стартового боя |

Профиль содержит `name`, `hp` (максимум), `ac`, `speed`, `proficiency`, шесть числовых `scores` (`STR`, `DEX`, `CON`, `INT`, `WIS`, `CHA`), `attacks`, список ID `abilities`. Допустимы непосредственные `features`, спасброски, навыки, чувства, сопротивления и тактика по контракту существующего адаптера. Активные атаки имеют уникальный `id`, `name`, `kind` (`melee`, `ranged`, `meleeSpell`, `rangedSpell`), `ability` либо явные `bonus` и `flat`, `count`, `die`, `range`, `damageType`. Поддержаны параметры имеющихся оружейных обработчиков: `light`, `mastery`, `unarmed`, `sneakEligible`, `normalRange`, привязка к инвентарю и стрелам. Неизвестное мастерство отклоняется.

`features` — уже реализованные механизмы ядра; это не произвольные метки. `extraAttack:2` означает две атаки за действие Атака, не две дополнительные. `masteries` принимает только `vex` и `nick`. `cunningAction` пока даёт бонусные Рывок и Отход; бонусное Скрытие ещё требует расширения. Не следует выдавать эту возможность за полный комплект разбойника.

Определение `handler:features` содержит объект `features`. Он соединяется с параметрами профиля; два разных значения одного параметра вызывают ошибку.

Определение `handler:onHitCondition` содержит `attacks` (ID атак), `condition` (`poisoned`, `prone`, `frost`), необязательный `name` и `save:{stat,dc}`. Для `poisoned` и `frost` длительность только `target-next-start` — до начала следующего хода цели. Для `prone` также доступно `until-removed` — пока не встанет/не снимет состояние. `frost` уменьшает скорость на 10 футов; сейчас это внутренний зарегистрированный эффект, а не универсальное правило холода.

Эффект запускается после обработки урона от попадания по живой цели. Попадание с полностью уменьшенным уроном всё ещё считается попаданием; это явно `onHit`, не `onDamage`. При указанном спасброске состояние применяется только при провале. Иммунитеты `conditionImmunities` предотвращают эти эффекты. Проверка идёт через обычный механизм спасбросков и вдохновения. Эффекты нескольких атак не делят изменяемые объекты. Самостоятельный урон ядом, повторные спасброски и другие длительности пока не поддержаны.

Ресурсы героя имеют `{current,max}`. Поддержаны `hp`, `focus`, `luck`, `heroic`, `arrows`, `unusual_metabolism`. Нельзя записать ячейки или новый ресурс и ожидать автоматического исполнения. Для них нужен обработчик и расширение контракта отчёта. Инвентарь: `id`, `quantity`, `combat_available`, необязательные название и тип расходника. Пустой инвентарь не создаёт предметы автоматически.

В сценарии `heroes` ссылаются на ID из `characters` либо явно указывают профиль союзника. `enemies` обязательно указывают `profile`. Числа КД, ПЗ и способности не переопределяются поверх профиля в размещении. `cell` — например `C4`, инициатива может быть задана либо будет определена при создании. Роли тактики: `ranged`, `guardian`, `skirmisher`, `pack`; поддержаны мораль, разрешение отступления, удержание позиции, якорь и радиус поиска.

Для сюжетного боя нужны действительный `source_state_sha256` пакета, `source_revision` и `source_state_sha256` сценария. Адаптер сверяет их до старта. Текст из книги или карточка в свободной форме не считается пакетом.
