# Кандидат 30.7.0: корректность, движение, реестр и журнал

Основа: `reider789/rin_dnd` @ `b0404d02754145e926e715681e68cfc72f22b75f`.
Это изменения общего движка. Имена героев, правила кампаний и их канонические состояния не меняются.

## Исправленные ошибки

- Отравление даёт помеху проверкам характеристик. Испуг даёт помеху атакам и проверкам только при видимом источнике. Иммунитеты и подавление состояния сохраняют приоритет. Помеха этих состояний не переносится на спасброски.
- Союзник, недееспособный из-за состояния, больше не даёт преимущество «Стая».
- ИИ и маршрут игрока используют `movementStep` ядра: соседство, угол стены, допустимость прохода/остановки, стоимость и запрет приближения при испуге. Алгоритм Дейкстры и выбранная стоимость диагонали сохранены. ИИ проверяет допустимость выбранной команды; недоступное действие заменяется Уклонением или завершением хода за один ограниченный шаг.
- Скрытые противники не превращаются в заранее известные препятствия. Для скрытого источника страха планировщик использует последнее наблюдение. Исполнение проверяет фактический шаг и останавливает заблокированный маршрут без исключения.
- Истощение явно отклоняется как неподдержанная механика. Уровни истощения не реализованы в этом изменении; старый файл с таким состоянием не переписывается. Ошибка предлагает разбор ведущим вместо молчаливого игнорирования штрафов.

## Ограниченный реестр

`CombatActivities.spell(id)` возвращает независимую именованную карточку: `name`, `level`, `cost`, `range`, `target`, `school`, необязательный `concentrationSeconds`, `handler`, `handlerVersion`, `automation`. Значение `supportedCombatSubset` не означает полноту всех внебоевых применений заклинания. `CombatMagic.SPELLS` остаётся совместимым представлением старых кортежей; новые потребители используют именованные поля.

Проверенные параметры лечения Cure Wounds и зелий находятся в `CombatActivities.HEALING`; сложные цепочки заклинаний и реакций остаются в существующих обработчиках. Новый обработчик пакета `healing` даёт возможность добавить **незаклинательное** лечебное действие через данные:

```json
{
  "handler": "healing",
  "version": 1,
  "name": "Полевая помощь",
  "cost": "action",
  "target": "ally",
  "range": 5,
  "dice": { "count": 2, "sides": 6, "flat": 2 },
  "resource": { "counter": "second_wind", "amount": 1 },
  "reference": "Пример согласованного действия, не стандартное Второе дыхание"
}
```

Пример задаётся в `abilities` пакета, его ID добавляется в `profiles.*.abilities`, а текущий `second_wind` — в ресурсы конкретного участника. Не добавляйте его автоматически к каноническим персонажам: источник и соответствие расходуемого ресурса должны быть согласованы. `requires: ["healing"]` позволяет старому движку отклонить пакет.

Контракт v1: действие или бонусное действие; на себя с дальностью 0 либо на живого союзника в пределах 0–60 футов и видимости; 1–12 костей к4/к6/к8/к10/к12 и добавка 0–30; один существующий зарегистрированный счётчик, расход 1–100. Неизвестные поля, формулы, скрипты, обработчики и ресурсы отклоняются. Команда: `{kind:"activity", actor, activity, target}`.

Проверяются бюджет действия, Slow/Abjure, ресурс, цель, дальность и видимость. Лечение проходит через существующие очередь, вдохновение, Beacon of Hope и ограничение максимальных ПЗ. UI создаёт кнопку из карточки и получает причину недоступности от ядра. Новое действие не является заклинанием и не открывает окно Counterspell. ИИ в этой версии не выбирает произвольные лечебные декларации; существующая тактика Второго дыхания сохранена. Новые типы действий требуют отдельного обработчика и тестов, а не произвольной программы в пакете.

## Подробный журнал

Раскрываемые «Подробности» и текстовый экспорт используют `CombatJournal.details/text`. JSON-экспорт — `{format:"dnd-combat-journal", version:1, engineVersion, battleId, events}`. Это диагностический журнал; для продолжения боя используется полный экспорт сессии.

- Броски: кости, выбранный d20, модификаторы, СЛ, причины преимущества/помехи. Уже выпавшие Bless и Mind Sliver записываются без дополнительных бросков.
- Урон: порядок уменьшений, иммунитет, сопротивление, уязвимость, временные ПЗ, фактическая потеря ПЗ. Спасброски урона заклинаний фиксируют промежуточный результат. Защитные ауры и магические поправки спасброска пока сгруппированы; это не полный реестр каждого источника модификатора.
- Концентрация: полученный урон и рассчитанная СЛ, включая случай поглощения временными ПЗ.
- Связи: необязательные `trace.actionId`, `rootActionId`, `parentActionId`, `command`, `actor` и поле `phase`. Корневая команда, решение игрока, автоматическая атака реакцией и Counterspell получают связи; продолжения возвращаются к своему исходному действию. Не каждая внутренняя пассивная способность получает отдельный ID — она остаётся этапом родительского действия.

`actionSerial` отделён от RNG. Метаданные сохраняются в задачах, окнах решения и этапах заклинаний. Ошибка команды откатывает счётчик, состояние и события. При загрузке старые события без новых полей продолжают читаться; их отсутствующие причины не восстанавливаются задним числом. Исторический `core/journal.js` v29 сохранён отдельно.

## Проверка и включение в кампании

```sh
python tools/build_rin.py
python tools/run_tests.py --suite all
python tools/run_tests.py --suite combat --browser
```

Новые регрессии: `tests/test_correctness_30_7.js`, `tests/test_activities.js`, `tests/test_journal.js`. Они проверяют независимый расчёт кратчайшего пути на малых сетках, скрытые позиции, допустимость ИИ, отсутствие двойной оплаты, откат ошибочных команд, вложенный Counterspell, точный порядок защит, равенство состояния и журнала после reload и отсутствие дополнительных RNG-вызовов. Новые тесты включены и в проверку переносимого SDK вне репозитория.

Для Хейвенгарда используется тот же SDK и `tools/build_shared_combat.py --engine-root PATH`. Кандидат проверяется через `tools/test_shared_handoff.py PATH`; канон не изменяется. До коммита кандидата старая опубликованная привязка `engine-lock.json` сохраняется. После решения о публикации требуется зафиксировать **реальный** SHA исходника, обновить контрольные суммы переносимого пакета, собрать обе страницы Хейвенгарда без `--development` и повторить интеграционные и браузерные проверки. Не подставлять SHA старой версии к новым файлам.

Новые зависимости исполнения и код сторонних репозиториев не добавлены. Зелёные тесты ядра/сборки не заменяют браузерную проверку новых кнопок, экспорта и раскрытия журнала.

## 30.7.1 — защита загрузки и актуальность памяти препятствий

Повреждённые новые поля журнала и память препятствий отклоняются до замены активной сессии и автосохранения. Отображение подробностей имеет безопасный текстовый fallback. Память неудачного шага сохраняется только при том же наблюдаемом контексте, инвалидируется при снятии страха, смене позиции/видимых препятствий и очищается на новом ходу. Скрытые позиции не входят в контекст. Старые записи без контекста удаляются при загрузке копии сессии.
