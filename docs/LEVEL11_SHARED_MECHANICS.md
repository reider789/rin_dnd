# Частичная поддержка 11-го уровня Хейвенгарда в общем ядре

Этот набор изменений НЕ является полным выпуском 11-го уровня, см. [задачу #13](https://github.com/reider789/rin_dnd/issues/13).

## Уже реализовано

- **Radiant Strikes** — зарегистрированная общая способность, дающая дополнительный бросок 1к8 излучением за каждое успешное оружейное попадание подходящего типа (или безоружный удар). Модель данных поддерживает `meleeWeapon: true` для метательных атак рукопашным оружием. На крит удваивается именно число кубов, а не плоский урон. Отдельный тип `radiant` позволяет правильно применять сопротивления, иммунитеты и другие защитные эффекты. Промах с Graze не считается попаданием и не вызывает Сияющие удары.
- **Chain Lightning** — VI круг, один общий бросок 10к8 урона молнией + Усиленное Воплощение при его наличии; у каждой выбранной цели самостоятельный спасбросок Ловкости. Первая видимая цель в 150 фт, до трёх других в 30 фт от первой. Выбранных союзников можно защищать Скульптурой заклинаний. Отмена заклинания Контрзаклинанием не запускает урон.
- Для молнии добавлена отдельная визуальная привязка по ID заклинания, без зависимости от русского текста.

## Ограничения, которые нельзя скрывать

- Поддержаны именно **цели-существа** Цепной молнии. Поведение при поражении обычных предметов требует отдельного обработчика объектов.
- `Improved Cunning Strike` (11 уровень) реализован: два **разных** эффекта за одну «Скрытую атаку», каждый расходует по одной базовой кости (по две кости после удвоения при крите). Существующий одиночный формат эффекта сохранён при импорте старых боёв. Реализация проверена в тестах Node.js; полный CI заблокирован несинхронизированным автономным пакетом.\n- `Globe of Invulnerability`: добавлена неподвижная 10-футовая зона концентрации, проверка уровня и точки сотворения внешних заклинаний, защита от прямых попаданий и типовых областей, сериализация и снятие зоны вместе с концентрацией. Это **первый реализованный охват**, а не завершённый аудит всех длительных зон и отложенных эффектов.\n- `Revivify`: добавлен обработчик в рамках **текущего боя** (покойный с подтверждённым временем смерти не старше минуты, касание, 1 ПЗ); алмаз стоимостью ≥300 зм учитывается и списывается из **физического инвентаря** по удостоверенному `casting.components.revivify.itemId`. При неизвестном времени смерти (в том числе после переноса между разными сценами) требуется решение Мастера, автоподъёма нет. Инвентарь Лютобора в каноне пока не содержит подтверждённого алмаза.
- `Tasha's Bubbling Cauldron` **не реализован**: все детали последовательности и запрет дублирования зелий записаны в [TASHA_CAULDRON_CONTRACT.md](TASHA_CAULDRON_CONTRACT.md). Подтверждённого позолоченного половника в каноне нет. Их нельзя включать в полностью автоматический пакет и обещать работоспособную готовую сборку отряда.
- Одно изменение справочной карточки или регистрация названия заклинания не равны полной поддержке правила. Перед обновлением закреплённой версии Хейвенгарда нужны тесты, CI, регенерация его боевого пакета и совместимость с сохранениями.

## Проверки

`tests/test_martial_features.js` — урон, крит, Graze, дальнобойное оружие, метание, сопротивление.
`tests/test_magic.js` — три теста Цепной молнии: отдельные спасброски, предел дальности и Скульптура.
`tests/test_visual_fx.js` — проверка наличия визуальной привязки для каждого зарегистрированного заклинания.

Генерируемые автономные файлы Рина должны соответствовать исходным модулям; после изменения ядра выполняется `python tools/build_rin.py`, затем `python tools/run_tests.py --suite combat --browser`.
