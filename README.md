# Рин Вейр — Campaign Engine и тактический бой v30.3
**Переход в новый чат (18.10.2026):** [docs/CHAT_HANDOFF_2026-10-18.md](docs/CHAT_HANDOFF_2026-10-18.md). Это проверенная точка восстановления сюжета и технической версии v30.3; игровое состояние не изменяется от чтения.


Откройте `index.html` в настольном браузере. Код, графика и карточки встроены в файл; сервер и подключение к сети для боя не нужны. Карта и действия расположены рядом. Встроенная засада — учебная реконструкция: её результаты не применяются к кампании.

Канон кампании: `state/_campaign-state.json`. Продолжение сюжета: `CAMPAIGN_ENGINE.md`, `views/scene-context.md`. При подготовке нового боя сборщик получает свежий снимок канона. Уже начатая сессия продолжает использовать собственную исходную карточку.

## Общее ядро и другие кампании

Движок больше не требует данных Рина для сборки. Пакет JSON описывает профили, общие способности, участников и сценарии. В интерфейсе есть «Загрузить пакет кампании»; неизвестные обработчики отклоняются до смены боя. Сохранение пакета содержит его данные и открывается в чистом браузере.

```sh
node sdk/cli.js validate examples/portable/border-watch.json
python tools/build_combat.py --pack examples/portable/border-watch.json --output dist/border-watch.html
python tools/export_engine.py --output dist/combat-engine.zip
```

Архив SDK проверяется распаковкой в отдельную папку и повторной сборкой без канона Рина. Пример содержит двух новых героев и авторского противника с ядовитыми когтями; его эффекты проходят обычные спасброски, вдохновение и JSON-продолжение. Схема и ограничения: `docs/CONTENT_PACKS.md`, запуск отдельно: `docs/PORTABLE_ENGINE.md`.

Хейвенгард пока остаётся на прежнем боевом интерфейсе: его полная библиотека способностей ещё не перенесена. `docs/havengard-migration-audit.json` фиксирует текущие карточки ревизии 29 и устаревание старого реестра ревизии 27. Наличие поддержанного примитива не означает готовности всего героя. Нельзя объявлять миграцию законченной, отключив остальные способности.

В v30.3 общая библиотека расширена ресурсами классов, манёврами, защитными реакциями и аурами. Учебный пакет `examples/portable/class-defense-lab.json` проверяет эти механизмы на других героях. Это частичные учебные профили, а не готовые карточки партии Хейвенгарда. Контракт: `docs/CLASS_FEATURES.md`, границы переноса: `docs/HAVENGARD_MIGRATION.md`.

## Что изменилось

- Активная боевая логика выделена в независимое от браузера ядро. Имена и классы участников не определяют базовые правила.
- Атаки, реакции, урон и концентрация проходят через общую очередь событий. Окна выбора имеют постоянный ID; повторное нажатие не применяет решение второй раз.
- Проверены Отражение атак и его отказ, перенаправление 5/60 футов, Тьма, Vex, Nick, Скрытая атака, Шквал, Удача, вдохновение, обмен инициативой Бдительного и Необычный метаболизм.
- Есть захват, освобождение, толчок, Помощь атакой, подготовленная атака, скрытие, поиск, атака выбранной клетки вслепую, несмертельный исход и спасброски от смерти.
- NPC выбирают позицию и действие с учётом дальности, помех, видимости, маршрута, риска и собственной роли. Есть отступление и помощь умирающему союзнику. Последнее известное место врага хранится отдельно от его настоящего положения; NPC обследует окрестности и помнит уже проверенные позиции. Прогноз атаки не получает сведения о незамеченных угрозах.
- Добавлены Второе дыхание, Тактический разум и сдвиг, Всплеск действий, Несгибаемость, семь манёвров, Graze/Sap/Push/Slow, Точный прицел, Надёжный талант, Невероятное уклонение, Наложение рук, ауры, Защита, Щит и защитные реакции предметов. Все используют общую очередь и явные текущие счётчики. Уклонение разбойника подключено к общему этапу урона от спасброска; библиотека заклинаний ещё требует переноса.
- JSON сохраняет очередь, незавершённый выбор и состояние генератора костей. Загрузка не перебрасывает уже полученные результаты.
- Сюжетный отчёт проверяется по ID кампании, ревизии и SHA-256 канона. Импорт ресурсов, предметов и времени использует существующие транзакции и квитанции Campaign Engine.

## Сборка и проверки

Требуются Python 3.12+ и Node.js 22+.

```bash
python tools/build_rin.py
python tools/run_tests.py
python -m pip install playwright==1.55.0
python -m playwright install chromium
python tools/run_tests.py --browser
```

`python tools/build_rin.py --check` проверяет актуальность всех сгенерированных файлов без записи. Смена класса или уровня требует проверки `config/combat_profiles.json`: сборка отказывается использовать старые способности с новой карточкой. Полная проверка включена в GitHub Actions.

## Сюжетный бой

1. Создать сценарий по образцу `encounters/caravan_ambush_training.json`, указать `kind: story`, уникальный `battle_id`, актуальные `source_revision` и `source_state_sha256` из снимка. Числа инициативы — готовые результаты; если их не указать, движок бросает инициативу с модификаторами, включая Бдительного.
2. Собрать: `python tools/build_rin.py --scene encounters/имя_сценария.json`. Сборщик отклоняет устаревший сюжетный сценарий. Сценарий также можно загрузить через интерфейс.
3. После завершения скачать «Итоги для мастера». Технический журнал содержит результаты бросков; художественное описание по нему пишет ведущий по `NARRATIVE_CONTRACT.md`.
4. Проверить транзакцию: `python tools/import_combat_result.py rin-battle-result.json`. Эта команда ничего не применяет.
5. После подтверждения сыгранного результата применить: `python tools/import_combat_result.py rin-battle-result.json --apply`. Повторный импорт идентичного отчёта — пустая операция. Изменённый отчёт с прежним ID или устаревший канон отклоняются.

Чат не получает результат самопроизвольно. Нужно передать экспорт ведущему. В браузер не помещаются планы GM, полный граф тайных знаний или ещё не сыгранные сюжетные события. Отчёт сохраняет исходы участников, но сопоставление временных боевых ID с сюжетными NPC и литературное продолжение остаются работой ведущего.

## Границы поддержки

Это проверяемая основа текущей кампании, а не реализация всех книг D&D. Новые способности NPC требуют зарегистрированного обработчика; неизвестные `features` отклоняются. Произвольные заклинания из старого движка не считаются автоматически поддержанными. Малая иллюзия создаёт заявку и запись согласованного решения ведущего; её смысловые последствия не выдумывает тактический ИИ. Полёт, верховой бой, многоуровневая геометрия, большие существа с несколькими клетками, сложные смешанные пакеты урона и детальный учёт занятых рук требуют отдельных расширений. Отдых и восстановление вне боя ведутся в Campaign Engine.

Файлы сохранений v29/v12 не импортируются в v30: это предотвращает продолжение с другими правилами и потерю незавершённой реакции. Старая версия доступна в истории GitHub. Файлы v29, `upstream_snapshot/`, `upstream_campaign/` и прежние `tests/qa_*` оставлены как исторический материал и не загружаются в v30.

Устройство системы и порядок добавления способностей: `ARCHITECTURE.md`. Результаты проверок: `QA_REPORT.md`.
